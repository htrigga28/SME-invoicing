# Lumina Marketing Evolution — Reference Library

**Status:** APPROVED REFERENCE SET  
**Decision date:** 2026-09-18  
**Scope:** `apps/marketing` only  
**Companion docs:**
- `docs/lumina-v2/05_MARKETING_SITE_REDESIGN.md`
- `docs/lumina-v2/11_CURRENT_MARKETING_UI_AUDIT.md`
- `docs/lumina-v2/12_MARKETING_REDESIGN_CODEX_PROMPT.md`

This document exists to keep the marketing redesign from drifting into generic SaaS styling or a random mixture of references.

The rule is simple:

> **Many references are provided, but every reference has a narrow assignment. Do not average them together.**

Lumina should feel like **financial software with an editorial marketing layer**: light, calm, trustworthy, product-led, and much more kinetic than the authenticated workspace.

# 8. What NOT to do

These rules are part of the reference library because visual drift usually happens here.

Do not:
- clone Stripe;
- average every reference into a generic SaaS look;
- use dark backgrounds as the default;
- use crypto gradients;
- invent 3D coins/cards;
- create abstract glass objects unrelated to receivables;
- use stock people as primary visual proof;
- build the page from equal feature cards;
- add testimonials/logos that do not exist;
- show recurring billing, reminder automation, collections queues, customer portal, forecasting, AI, NRS integration, or ERP integrations as shipped before they are built;
- use a reference's feature merely because its UI looks good;
- introduce a new brand font during implementation;
- use Pinterest as proof of product behavior.

The hierarchy is:

> Lumina product truth → Lumina app design → this reference assignment → external visual inspiration.

External inspiration never overrides product truth.
